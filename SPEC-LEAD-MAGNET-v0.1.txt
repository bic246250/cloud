1. WHAT WE'RE BUILDING
================================================================================

A dedicated landing page that trades an email address for the Pregnancy
Weight Gain Control System PDF. Plus a server-side form handler that
forwards submissions to MailerLite.

Two files to create:
  - src/pages/download/pregnancy-weight-gain-system.astro   (the page)
  - functions/subscribe.js                                  (the handler)

Plus one config file:
  - wrangler.toml                                           (Pages Functions binding)

No new npm dependencies. Astro 7 is already installed.

================================================================================
2. WHY A PAGES FUNCTION (not a client-side form)
================================================================================

The MailerLite API key must never reach the browser. A Pages Function
keeps it in Cloudflare's server-side environment (secrets), so:

  - No API key in source code or git history
  - No CORS issues (same-origin POST)
  - Can validate and sanitize input before forwarding
  - Can return structured JSON for client-side success/error display

Cloudflare Pages Functions are already supported by the hosting plan.
No extra cost, no extra infrastructure.

================================================================================
4. FORM HANDLER: functions/subscribe.js
================================================================================

4.1 ENDPOINT
  POST /functions/subscribe

4.2 EXPECTED PAYLOAD (JSON)
  {
    "email": "user@example.com",
    "due_date": "2026-03-15",       // optional
    "consent": true                   // required, must be true
  }

4.3 VALIDATION (server-side, return 400 on failure)
  - email: required, valid format (regex), max 254 chars
  - consent: must be `true`
  - due_date: optional, if present must be YYYY-MM-DD format

4.4 MAILERLITE API CALL
  POST https://connect.mailerlite.com/api/subscribers
  Headers:
    Authorization: Bearer <MAILERLITE_API_KEY>
    Content-Type: application/json
    Accept: application/json
  Body:
    {
      "email": "<email>",
      "groups": ["<GROUP_ID>"],
      "fields": {
        "due_date": "<due_date>"       // only if provided
      },
      "resubscribe": true
    }

  NOTE: Double opt-in is configured at the MailerLite group level
  (Settings → Double opt-in). When enabled, MailerLite sends a
  confirmation email automatically. We do NOT implement double
  opt-in in code.

4.5 RESPONSE
  Success (200 or 201 from MailerLite):
    { "ok": true, "message": "Check your inbox — the PDF is on its way." }

  Error (400/500):
    { "ok": false, "error": "<human-readable message>" }

4.6 GROUP ID
  We need a MailerLite group for lead magnet subscribers.
  Suggested name: "Pregnancy Weight Gain System"
  (Create it in the dashboard, note the ID, store in .env or pass
  via Pages Function environment variable.)

4.7 ENVIRONMENT VARIABLES (set in Cloudflare Pages dashboard)
  - MAILERLITE_API_KEY (secret)
  - MAILERLITE_GROUP_ID (plaintext)

================================================================================
5. CLIENT-SIDE FORM BEHAVIOR
================================================================================

The Astro form uses `fetch()` to POST to /functions/subscribe.

  - On submit: disable button, show "Sending..."
  - On 200: hide form, show success message + "Check your inbox" + a
    secondary CTA to /guides/pregnancy-weight-gain/
  - On error: show error message inline, re-enable button
  - No page reload. No external JS libraries.

  The form is progressively enhanced: without JS it does nothing
  (Astro renders static HTML). This is fine — JS is required for
  the site's calculators anyway.

7. OPEN QUESTIONS FOR BIC
================================================================================

  A. Due date field: keep it optional on the form?
     PRO: enables date-triggered email sequences later.
     CON: extra friction on the form.
     RECOMMENDATION: keep it optional, low friction.

  B. GDPR consent checkbox: required (opt-in) or pre-checked (opt-out)?
     RECOMMENDATION: required, unchecked by default. GDPR standard.

  C. Should we also offer the PDF as a free download on the
     /guides/pregnancy-weight-gain/ page (no email required)?
     RECOMMENDATION: No. The guide is free content. The PDF is the
     gated asset. Keep them separate.

  D. PDF hosting: where will the PDF file live?
     Options: Cloudflare R2, MailerLite attachment, or a public URL
     on the site (e.g., /downloads/pregnancy-weight-gain-system.pdf).
     RECOMMENDATION: Start with MailerLite attachment (simplest).
     Migrate to R2 or a CDN later if download volume grows.
